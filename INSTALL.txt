FANTASY MPL — PROFILE PERSISTENCE AND STARTUP RECOVERY

A. DATABASE FIRST
1. Open Supabase Dashboard > SQL Editor.
2. Run:
   supabase/migrations/023_atomic_profile_updates.sql
3. Expected:
   atomic_profile_save_ready: true
   account_bootstrap_ready: true

B. APPLICATION FILES
1. Copy the CONTENTS of this folder into the repository root.
2. Do not copy the outer fantasy-mpl-profile-persistence-recovery folder.
3. Replace matching files.

C. COMMIT
  Fix profile persistence and account startup recovery

D. VERIFY AFTER DEPLOYMENT
Use a normal non-admin account:
1. Change manager name and bio, then save.
2. Wait for: Profile updated and confirmed by Supabase.
3. Refresh and confirm the values remain.
4. Upload a small JPG/PNG/WebP, save, refresh and confirm it remains.
5. Sign out and sign back in, then confirm the same profile data remains.

BEHAVIOR CHANGES
- Profile success appears only after Supabase confirms the atomic update.
- Upload/save operations time out with a real error instead of false success.
- Account startup uses one bootstrap RPC instead of three profile requests.
- Duplicate initial auth hydration is removed.
- A failed/slow startup shows a retry screen after 12 seconds instead of an endless Preparing the arena screen.
